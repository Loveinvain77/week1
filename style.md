# Our coding style
- Choose descriptive variable and function names so others can understand what they store or calculate. Avoid vague single letters like x or y.
- Each function should only do one single task. If a function tries to handle many different things, split it into smaller pieces.
- Write comments only when the logic is tricky and hard to understand. Do not add redundant comments that just repeat what the code already shows.
- Keep indentation the same everywhere in the project, for example always use 4 spaces. Do not mix spaces and tabs.
- Every project must include a README file, which explains how to open, run and test the code.
- Delete old code that has been commented out. Do not leave unused commented lines in your final files.
- Keep lines reasonably short. Very long lines are hard to read on small screens.
